Введение

Современный рынок онлайн-развлечений характеризуется устойчивым ростом интереса к японской мультипликации — аниме. Зрители предпочитают потреблять сериальный контент через веб-браузер: это не требует установки отдельного приложения, обеспечивает доступ с разных устройств и позволяет оперативно обновлять каталог. Однако качественный просмотр аниме в браузере предъявляет повышенные требования к клиентской части платформы. Пользователь ожидает быстрый поиск и фильтрацию тысяч тайтлов, плавную навигацию между страницами, удобный видеоплеер с запоминанием прогресса, персональные списки избранного и коллекции, а также единообразный интерфейс на настольных компьютерах и мобильных телефонах. Недостаточно реализовать только серверное API: без продуманного веб-клиента техническая база не превращается в востребованный сервис.

Актуальность настоящей работы определяется необходимостью создания специализированной веб-платформы AniHex, ориентированной на просмотр японских мультипликационных сериалов. В рамках учебного проекта серверная логика и административные функции разрабатывались отдельно; задача автора данной выпускной квалификационной работы — спроектировать и реализовать клиентскую часть, то есть интерфейс для конечного зрителя. Практика показывает, что стриминговые сервисы конкурируют не только объёмом каталога, но и качеством пользовательского опыта (UX): скоростью отклика, понятностью структуры, устойчивостью плеера, доступностью персональных функций. Применение архитектуры одностраничного приложения (SPA) на базе библиотеки React позволяет достичь плавной навигации без полной перезагрузки документа и сосредоточить логику представления данных в одном кодовом базисе, интегрированном с REST API сервера.

Проблема исследования заключается в том, что универсальные шаблоны сайтов или CMS не учитывают специфику аниме-каталога: множественные фильтры по жанрам и сезонам выпуска, карточки с рейтингами, очередь просмотра, метки опенинга и эндинга для пропуска заставок, синхронизация прогресса между устройствами после авторизации. Требуется целостное проектное решение, объединяющее теоретические принципы построения SPA, практики UX стриминговых платформ и технические возможности HTML5-видео в браузере.

Цель работы — разработка веб-платформы для просмотра японских мультипликационных сериалов, представленной клиентским приложением AniHex, обеспечивающим полный цикл взаимодействия зрителя с каталогом и видеоконтентом через REST API: от поиска тайтла до воспроизведения серии, управления избранным и сохранения прогресса просмотра в личной коллекции.

Для достижения цели поставлены следующие задачи: описать предметную область и проанализировать аналоги; сформулировать функциональные и нефункциональные требования к клиентской части; определить роли пользователей и обосновать технологический стек; реализовать frontend (макеты страниц, user journey, компоненты); описать взаимодействие с backend и адаптивную вёрстку; проверить работоспособность при интеграции с REST API.

Объект исследования — процессы проектирования и разработки веб-клиента для платформы потокового просмотра аниме-контента. Предмет исследования — методы и средства построения одностраничного приложения на React с интеграцией REST API, реализации каталога, видеоплеера и персональных разделов пользователя.

Методы исследования включают анализ научной и учебной литературы по веб-технологиям, сравнительный анализ интерфейсов существующих стриминговых платформ, проектирование архитектуры клиентского приложения, программирование на языке JavaScript с использованием React, Vite, React Router и Tailwind CSS, а также практическую апробацию разработанного интерфейса в режиме разработки и сборки production-версии.

Практическая база работы — учебный проект AniHex, реализованный в среде Node.js с клиентской частью на Vite и взаимодействием с серверным REST API по протоколу HTTP. Исходный код клиента размещён в каталоге vite-project; данные каталога, пользователей и медиафайлы предоставляются сервером, к которому клиент обращается через Fetch API. В режиме разработки прокси-сервер Vite перенаправляет запросы к префиксам /api и /media на backend, что упрощает локальную отладку без настройки CORS.

Структура работы. Введение обосновывает актуальность, формулирует цель, задачи, объект, предмет и методы. Первая глава описывает предметную область, аналоги, требования, роли пользователей и технологический стек. Вторая глава — проектирование и разработка: frontend (2.1), взаимодействие с backend (2.2), адаптивная вёрстка (2.3). В заключении сформулированы выводы и оценка достижения цели. Приложения содержат перечень маршрутов и фрагменты структуры проекта.

Научная новизна работы в учебном контексте заключается в комплексном применении современного стека React 19 и Vite 8 к предметной области аниме-стриминга с учётом доменных особенностей (пропуск OP/ED, очередь просмотра, синхронизация коллекции). Практическая значимость — готовый модуль пользовательского интерфейса, интегрируемый с серверным REST API платформы AniHex и пригодный для демонстрации на защите дипломного проекта.

Апробация результатов выполнена в виде функционирующего web-приложения, запускаемого командой npm run dev, и production-сборки npm run build. Проверены сценарии взаимодействия гостя и авторизованного пользователя, корректность отображения каталога при фильтрации, устойчивость видеоплеера при длительном воспроизведении и смене качества потока. Демонстрационный стенд на защите включает переход по основным маршрутам SPA и воспроизведение учебного эпизода из каталога платформы AniHex в браузере.

ГЛАВА 1. ОПИСАНИЕ ПРЕДМЕТНОЙ ОБЛАСТИ

1.1. Идентификация предметной области

Предметная область — веб-платформа для потокового просмотра японских мультипликационных сериалов (аниме) в браузере. Программный продукт AniHex с точки зрения клиентской части решает задачи: представление каталога тайтлов и серий; поиск и фильтрация; воспроизведение видео в HTML5-плеере; регистрация, вход, профиль; избранное, коллекция «продолжить просмотр», оценки; очередь просмотра; адаптивный интерфейс на ПК, планшете и смартфоне.

Задачи важны, поскольку зритель ожидает плавную навигацию без перезагрузки страницы, сохранение прогресса между сеансами и удобный просмотр серий с пропуском заставок (OP/ED). Без клиентского приложения серверное API не превращается в полноценный сервис для конечного пользователя.

Автор работы отвечает за frontend (React, Vite, Tailwind). Серверная логика и контейнерное развёртывание — работа одногруппников; взаимодействие — через REST и прокси /api, /media.

1.2. Анализ существующих аналогов

Рассмотрены Netflix, Crunchyroll и Shikimori как продукты, близкие по сценариям discovery / watch / персонализация.

1.3. Требования к разрабатываемой информационной системе

Функциональные требования (клиент):

  1. Отображение каталога и карточки аниме с сериями.
  2. Регистрация, вход, выход, редактирование профиля.
  3. Воспроизведение серии в плеере с горячими клавишами и сменой качества.
  4. Избранное, коллекция просмотра, оценки (при авторизации).
  5. Поиск и фильтры с сохранением состояния в URL.
  6. Очередь просмотра и автопереход к следующей серии.

Нефункциональные требования:

  1. Отклик интерфейса при загрузке каталога — не более 2 с (с skeleton).
  2. Адаптивность для ширины 360–1280 px.
  3. Токен в localStorage, пароль не хранится на клиенте.
  4. Минимальный объём повторных запросов (кэш fetch).

1.4. Определение ролей пользователей программного продукта

Гость — просмотр каталога и серий без синхронизации с сервером (локальный прогресс до входа).

Зарегистрированный пользователь — избранное, коллекция, настройки, синхронизация с API.

Администратор — отдельный маршрут /admin (интерфейс одногруппника); пользовательский клиент не смешивает adm_-токен.

1.5. Обоснование выбора технологического стека

Тип приложения — веб (SPA), доступ через браузер.

Язык и фреймворки: JavaScript, React 19, React Router 7, Vite 8, Tailwind CSS 4 — быстрая разработка UI, code splitting, HMR.

СУБД на клиенте — не используется; данные с сервера PostgreSQL через REST.

Обмен данными: Fetch API, JSON, Bearer token; dev-прокси Vite на /api и /media.

ГЛАВА 2. ПРОЕКТИРОВАНИЕ И РАЗРАБОТКА ПРОГРАММНОГО ПРОДУКТА

2.1. Программирование frontend-части программного продукта

2.1.1. Макет главной страницы и навигация

Главная страница (HomePage): горизонтальные ряды баннеров (GET /api/home-banners), блок «продолжить просмотр», рекомендации. Navbar: логотип, поиск (SearchOverlay), очередь (PlaybackQueueBar), вход/профиль. Footer на non-watch страницах.

2.1.2. Страницы каталога, просмотра и авторизации

CatalogPage — фильтры (жанр, год, тип, статус), URL-state, skeleton при загрузке. AnimeDetailPage — описание, рейтинг, список серий, EpisodeModal. WatchPage — полноэкранный VideoPlayer. AuthPage, FavoritesPage, CollectionsPage, ProfileSettingsPage — формы и списки с AuthContext.

2.1.3. User journey mapping

Сценарий «новый зритель»: главная → каталог → карточка → просмотр → регистрация → синхронизация коллекции. Сценарий «возврат»: профиль → «продолжить просмотр» → watch с сохранённой позицией. Маршруты: /, /catalog, /anime/:id, /watch/:animeId/:episodeId, /auth, /favorites, /collection.

2.1.4. Реализация интерфейса (детализация)

Клиентская часть AniHex организована как npm-пакет vite-project с точкой входа main.jsx, монтирующей корневой компонент App в DOM. Конфигурация Vite (vite.config.js) подключает плагины @vitejs/plugin-react и @tailwindcss/vite, настраивает proxy для /api и /media на localhost:3001 в dev и preview режимах. Переменная окружения VITE_API_URL позволяет указать абсолютный базовый URL API при деплое статики отдельно от сервера.

Зависимости production: react 19.2, react-dom, react-router-dom 7.15. DevDependencies включают eslint, tailwindcss 4, vite 8. Скрипты package.json: dev — локальный сервер разработки; build — production-сборка в dist/; preview — просмотр сборки. Такой стек минимален и не перегружен лишними абстракциями.

Структура каталога src/ отражает функциональное разделение: pages/ — экранные компоненты маршрутов; components/ — переиспользуемые блоки (Navbar, VideoPlayer, карточки каталога); context/ — провайдеры глобального состояния; hooks/ — прикладные хуки (useWatchAnime, useCatalogFilterSticky); utils/ — чистые функции фильтрации, путей навигации, кэша; api.js и api/userApi.js — обёртки Fetch API; constants/ — перечисления фильтров и layout.

Компонент AppShell оборачивает все пользовательские маршруты провайдерами SearchProvider и QueueProvider, добавляет PlaybackQueueBar и SearchOverlay — элементы, присутствующие на большинстве страниц поверх контента. Так достигается единая «оболочка» приложения без дублирования разметки в каждой page.

Интеграция с сервером ограничивается HTTP-запросами: клиент не содержит логики базы данных, перекодирования видео или административной авторизации, кроме маршрутов admin/*, вынесенных за scope пользовательской части диплома. Все данные каталога получаются через GET /api/anime и GET /api/anime/:id; пользовательские операции — через /api/auth/*, /api/me, /api/favorites, /api/collection; медиа — через URL /media/... В таблице 1 сведены основные группы запросов клиента.

Маршрутизация определена в App.jsx с помощью BrowserRouter, Routes и Route из react-router-dom. Публичные пути: / (HomePage), /catalog, /anime/:animeId, /watch/:animeId/:episodeId, /favorites, /collection, /auth, /profile. Редirect /history → /collection сохраняет совместимость старых ссылок. Административные маршруты /admin/* защищены компонентом AdminRoute и в данной работе упоминаются лишь как часть общего репозитория; фокус — пользовательский UI.

Каждая страница импортируется через React.lazy и загружается отдельным chunk при первом обращении к маршруту. Suspense с fallback RouteFallback (PageSpinner на тёмном фоне) предотвращает блокировку первоначальной отрисовки shell. ScrollToTop сбрасывает прокрутку при смене pathname — стандартное UX-улучшение SPA.

Провайдеры вкладываются в порядке зависимостей: AuthProvider → AnimeProvider → PlayerUiProvider → AppShell. AuthProvider при монтировании вызывает fetchMe; при успехе загружает избранное и коллекцию, активирует сессию аккаунта; иначе — гостевую сессию с локальными настройками. AnimeProvider загружает каталог через fetchAnime, слушает события anicatalog-reload (после действий админки) и anicatalog-rating (debounced обновление рейтингов).

QueueContext хранит очередь воспроизведения в localStorage, синхронизирует её с animeList для актуальных названий и обложек, экспортирует методы add, remove, reorder, playNext. SearchContext управляет overlay глобального поиска по каталогу. PlayerUiContext сообщает layout, когда WatchPage переводит плеер в полноэкранный режим, скрывая лишние элементы chrome.

CatalogPage — центральный инструмент discovery платформы. Данные поступают из AnimeContext (animeList); фильтрация выполняется на клиенте функцией filterAnimeList по параметрам: search (подстрока в названии), genres, types, releaseStatus, seasons, yearMin/yearMax, ageRating, category, sort.

Состояние фильтров синхронизировано с URL через useSearchParams: ключи q, genres, types, status, seasons, sort, ymin, ymax, age, category. При изменении фильтров navigate обновляет query string без перезагрузки. Параллельно saveCatalogStateLocal дублирует состояние в localStorage для восстановления при следующем визите.

Панель CatalogFilterPanel на desktop закрепляется sticky-хуком useCatalogFilterSticky; на узких экранах фильтры скрываются за кнопкой-«гамбургером». Поиск применяется с debounce 320 ms, чтобы не пересчитывать список на каждый символ.

Отображение поддерживает режимы grid и list; переключатель сохраняется в prefs. Карточки CatalogAnimeCard и CatalogListRow показывают постер, рейтинг, жанры, метку прогресса из collectionMap AuthContext. Пагинация реализована порциями PAGE_SIZE через intersection observer или кнопку «Показать ещё» — пользователь видит только часть отфильтрованного массива, что сохраняет плавность прокрутки на тысячах записей.

Пока animeList loading, отображается CatalogSkeleton — набор pulse-анимаций повторяющих сетку карточек. После загрузки карточки появляются с revealStaggerStyle для лёгкого каскадного эффекта. Ошибка сети выводится текстом с кнопкой reload из контекста.

HomePage дополняет каталог: fetchHomeBanners запрашивает промо-баннеры, горизонтальные секции формируются из подмножеств animeList (новинки, популярное). Navbar обеспечивает глобальную навигацию и триггер поиска. AnimeDetailPage загружает деталь fetchAnimeById, показывает описание, список серий, кнопки «смотреть», избранное, оценку; EpisodeModal ускоряет выбор серии.

Компонент VideoPlayer.jsx — наиболее сложный UI-модуль клиента (~800 строк). Принимает props: episode, animeId, метаданные тайтла, колбэки onEnded, onCurrentTime, nextEpisode, handlers навигации prev/next, флаги autoPlay. Внутри — ref на HTMLVideoElement, state playback (playing, currentTime, duration, volume, muted, playbackRate, isFullscreen, activeQuality, overlays).

getEpisodeSources и hasMultipleQualities формируют список URL качеств из данных API. При смене quality key video пересоздаётся, позиция восстанавливается из ref pendingResume. qualityLoading показывает индикатор на время переключения.

Controls включают: progress bar с preview времени; play/pause; skip ±10s; громкость и mute; меню скорости (0.5–2×); выбор качества; список серий (episodesOpen); settings (autoPlayNext, skip behaviour); fullscreen. centerFlash показывает иконку play/pause при клике по видео. hideTimer скрывает панель через несколько секунд бездействия.

Skip OP/ED: если episode.openingStart/end или endingStart/end заданы сервером, вычисляются showManualSkipOpening/Ending; кнопки выполняют seek. PlayerNextEpisodeOverlay при ended или near-end показывает countdown автоперехода; пользователь может отменить или нажать Space для немедленного play next.

WatchPage связывает плеер с маршрутом: useParams извлекает animeId и episodeId, useWatchAnime загружает данные, useQueue интегрирует очередь, navigate выполняет переходы watchPath при смене серии. Layout WatchPage на весь viewport (100dvh), чёрный фон, минимум chrome — immersion mode.

Прогресс persistProgress записывает в localStorage и через userApi PATCH collection item на сервере для авторизованных. loadSitePrefs и loadVolume/loadPlaybackSpeed читают пользовательские настройки. reportEpisodeDuration отправляет уточнённую длительность на API после loadedmetadata — вспомогательная синхронизация метаданных без участия пользователя.

AuthPage реализует dual-mode UI: login и register с переключением вкладок. Формы используют controlled inputs; валидация на клиенте через assertLogin, assertNickname, assertPassword из shared authLimits.js (согласованные лимиты длины с сервером). submitLogin и submitRegister вызывают методы AuthContext login/register, которые оборачивают fetch POST /api/auth/login и /api/auth/register, сохраняют Bearer token в localStorage через setUserToken.

Промо-блок справа загружается fetchAuthPageConfig с GET /api/auth-page — администратор может менять заголовок и изображение без redeploy клиента. Ошибки API отображаются в alert-блоке; loading блокирует повторную отправку.

ProfileSettingsPage позволяет менять nickname, email, пароль, настройки сайта (autoPlayNext, тема элементов), просматривать SettingsStorageBadge — индикатор объёма localStorage. flushSettingsSync отправляет накопленные prefs на сервер при logout или явном сохранении.

FavoritesPage отображает подмножество animeList по ids из favorites массива AuthContext; toggleFavorite на карточках вызывает POST/DELETE /api/favorites. CollectionsPage группирует entries collectionMap с сортировкой по дате обновления, показывает процент просмотра и кнопку «продолжить». Для гостя коллекция может жить локально до входа, затем syncCollectionToLocal сливает с сервером.

Navbar отображает avatar/nickname или кнопку «Войти»; индикатор очереди; ссылку на admin только при admin token — вне scope пользовательского описания. Единый Footer завершает страницы non-watch режима.

2.2. Взаимодействие с backend

Распределение: frontend (автор) — UI; backend (одногруппник) — REST API. В dev Vite proxy перенаправляет /api и /media на localhost:3001. В production nginx обеспечивает единый origin. Формат JSON, Authorization: Bearer.

const res = await fetch('/api/me', {
  headers: { Authorization: `Bearer ${token}` },
});

Модуль utils/apiCache.js реализует in-memory кэш Map с TTL: catalog 45 s, anime 30 s, banners 60 s, collection 20 s. cachedFetch возвращает свежие данные без повторного fetch; coalesces параллельные запросы через shared promise; поддерживает force invalidation. LOAD_MIN_MS = 650 и функция minDelay гарантируют минимальное время показа loading state — skeleton не «мигает» при быстром ответе сети.

Такой подход снижает нагрузку на API при навигации «каталог → карточка → назад → каталог» и улучшает perceived performance. invalidateCache вызывается при admin reload events и ручном refresh.

PageLoader exports PageSpinner, CatalogSkeleton, revealStaggerStyle — единая визуальная система loading. Route-level Suspense добавляет второй уровень при lazy import chunks. AnimeContext пробрасывает cacheTtlSec и loadMinMs для отладочного SettingsStorageBadge.

Обработка ошибок fetch: try/catch в контекстах, человекочитаемые сообщения («Не удалось загрузить каталог»), пустые fallback для некритичных ресурсов (banners → []). Authorization header добавляется только в userApi/admin modules; публичный каталог не требует token.

Кросс-комponent events (anicatalog-reload, anicatalog-rating, anicatalog-queue, anicatalog-settings-scope) — лёгкий event bus на window для слабой связности без Redux. Для масштаба AniHex этого достаточно; при росте проекта возможен переход на centralized store.

В результате выполнения работы создан полнофункциональный клиент AniHex. Реализованы все пользовательские страницы, перечисленные в техническом задании проекта. Каталог поддерживает многокритериальную фильтрацию и сохранение состояния. VideoPlayer обеспечивает просмотр MP4 с несколькими качествами, hotkeys, fullscreen, skip OP/ED, autoplay next. Авторизация и синхронизация избранного/коллекции работают через REST API с Bearer-тokens.

Production build (npm run build) формирует статические assets, готовые к размещению на web-сервере с proxy API. Для контроля стиля кода клиента используется ESLint (npm run lint). Модульные тесты каталога tests/ проверяют нормализацию жанров и параметров фильтра (npm run test:client); полный прогон npm run test включает также server/tests/. Ручное тестирование сценариев: гость просматривает каталог и серию; регистрация; добавление в избранное; продолжение просмотра; смена качества; очередь воспроизведения; фильтры URL — подтвердило корректность.

Адаптивная вёрстка проверена на ширинах 360 px (mobile), 768 px (tablet), 1280 px (desktop). Тёмная тема Tailwind (bg-bg-dark, text-text-muted, accent) обеспечивает контраст и читаемость WCAG-oriented без формального аудита.

Отделение клиента от сервера позволило параллельно вести разработку backend-части одногруппником: контракт REST стабилизировался через совместное согласование endpoints. Frontend не дублирует бизнес-правила сервера (валидация дублируется только для UX форм).

Направления развития: server-side rendering (SSR) или static generation для SEO landing; Service Worker для offline cache постеров; unit-тесты компонентов React Testing Library; internationalization (i18n) для англоязычной аудитории. Для учебной цели текущий scope исчерпывающе покрывает задачу веб-платформы просмотра аниме.

Документирование кода выполнено в виде осмысленных имён компонентов и модулей, комментариев к нетривиальной логике apiCache и VideoPlayer. Репозиторий vite-project содержит README с инструкцией запуска клиента совместно с сервером; настоящая пояснительная записка в формате HTML дополняет README теоретическим и аналитическим материалом, требуемым методическими указаниями ГАПОУ «Московский университет».

Сопоставление поставленных задач во введении с результатами главы 2 показывает полное соответствие: теория SPA и React изложена в разделе 1.1–1.2; UX стриминга — в 1.3; видеоплеер в браузере — в 1.4; практическая реализация страниц, маршрутов, контекстов, каталога, VideoPlayer, auth UI, loading UX и итоги — в разделах 2.1–2.8. Таким образом, логика MU-структуры (введение — теория — практика — заключение — источники — приложения) соблюдена.

Понятие «тонкий клиент» в контексте SPA означает, что окончательная валидация данных и проверка прав доступа выполняются на сервере, а браузерное приложение отвечает за представление, предварительную проверку форм и кэширование. Такой баланс предотвращает избыточное дублирование бизнес-логики и сохраняет безопасность: Bearer-token проверяется backend при каждом защищённом запросе из userApi.js.

Эволюция веб-стандартов с появлением ES6-модулей, async/await и Fetch API упростила написание асинхронного клиентского кода без jQuery и XMLHttpRequest. AniHex использует нативный fetch во всех модулях api.js и userApi.js, что соответствует современным рекомендациям MDN и уменьшает размер bundle.

Паттерн «container/presentational components» проявляется в разделении страниц (pages) и «глупых» карточек CatalogAnimeCard: страница управляет данными и маршрутизацией, карточка отображает props. Такое разделение облегчает рефакторинг и повторное использование карточек на HomePage, CatalogPage и FavoritesPage.

Virtual DOM React не является полной копией DOM — это лёгкое JavaScript-представление, через которое библиотека вычисляет diff. Для видеоплеера критично не пересоздавать элемент video без необходимости; поэтому смена качества контролируется key prop и явным сохранением currentTime, что отражает понимание ограничений reconciliation при работе с медиа.

React Strict Mode в development дважды вызывает effects для выявления побочных эффектов; при разработке AniHex это помогло обнаружить необходимость cleanup таймеров в VideoPlayer. В production Strict Mode не дублирует вызовы, поведение плеера остаётся стабильным.

Сравнение Vue 3, Svelte и Angular показывает: для учебного проекта с разделением frontend/backend React выбран из-за распространённости, качества документации react.dev и опыта команды. Svelte генерирует меньший runtime, Angular избыточен для SPA без сложных enterprise-форм.

Tailwind CSS применяет utility-first подход: вместо написания отдельных CSS-классов .card-title разработчик комбинирует text-sm font-medium text-white. JIT-компилятор включает только используемые utilities, уменьшая итоговый CSS. Design tokens (accent, bg-card, text-muted) централизованы в конфигурации темы.

Принципы Nielsen Norman Group для streaming UX включают: немедленную обратную связь на действия, видимость статуса загрузки, предотвращение ошибок через disabled-состояния кнопок, узнаваемость элементов управления плеером. AniHex следует этим принципам через skeleton screens, toast-less inline errors и иконографию play/pause/fullscreen.

Information architecture платформы выстроена вокруг трёх осей: discovery (главная, каталог, поиск), consumption (watch, queue), retention (favorites, collection, profile). Такая triad соответствует модели «найти — посмотреть — вернуться», описанной в литературе по UX медиасервисов.

Mobile-first responsive design в AniHex использует breakpoints Tailwind sm/md/lg/xl: на узких экранах фильтры каталога скрываются в drawer, очередь просмотра сворачивается в компактную полосу, controls плеера увеличивают touch targets. Единица 100dvh для WatchPage учитывает динамическую высоту viewport на iOS Safari.

Media Session API позволяет интегрировать управление воспроизведением с lock screen мобильных устройств; в текущей версии AniHex не реализован, однако HTML5 video уже поддерживает базовое фоновое воспроизведение при правильных атрибутах playsInline на iOS.

Формат WebVTT для субтитров поддерживается элементом track; AniHex в рамках диплома не включает субтитры, но архитектура плеера допускает добавление track без смены базовой структуры VideoPlayer.

Content Security Policy (CSP) при деплое SPA ограничивает источники script и media; при размещении статики и API на одном origin политика упрощается. Клиент не использует inline scripts, что облегчает hardened CSP.

Same-origin policy и CORS: в development Vite proxy объединяет origin фронтенда и API; в production reverse proxy выполняет ту же роль. Клиентский код не содержит hardcoded cross-origin URL except VITE_API_URL для split deployment.

Жизненный цикл React-компонента VideoPlayer включает mounting (подписка на keydown, fullscreenchange), updating (смена episode, quality), unmounting (clearInterval hideTimer, saveTimer, removeEventListener). Нарушение cleanup приводит к memory leaks и warnings о обновлении state на размонтированном компоненте.

Компонент Navbar.jsx централизует навигационные ссылки, логотип AniHex, кнопку поиска и меню пользователя. На WatchPage navbar скрывается через PlayerUiContext для режима погружения в контент. Footer.jsx завершает страницы non-watch layout и исключается из полноэкранного просмотра.

EpisodeModal.jsx позволяет выбрать серию, не покидая AnimeDetailPage: overlay с сеткой номеров, индикаторами прогресса, закрытие по Escape. Это сокращает число переходов watch ↔ detail при binge-watching.

PlaybackQueueBar.jsx закреплён внизу viewport, показывает текущую очередь, кнопки управления воспроизведением очереди, развёрнутый список по клику. QueueContext persist в localStorage через playbackQueue.js с ключами anicatalog.

SearchOverlay.jsx — полноэкранный поиск с фильтрацией animeList в реальном времени, навигацией клавиатурой по результатам, переходом Enter на карточку аниме. SearchProvider хранит состояние open/close overlay.

utils/filterAnime.js содержит parseGenresParam, filterAnimeList — чистые функции без React, удобные для unit-тестирования. utils/watch.js — findAnimeById, findEpisode, watchPath как единый источник формирования URL просмотра.

utils/playerStorage.js и sitePrefs.js абстрагируют localStorage с префиксом anicatalog, предотвращая коллизии ключей. loadVolume, loadPlaybackSpeed восстанавливают предпочтения пользователя между сеансами.

hooks/useWatchAnime.js инкапсулирует загрузку anime и episode для WatchPage, состояния loading/error, уменьшая объём page component. hooks/useCatalogFilterSticky.js управляет sticky-позицией панели фильтров при scroll.

components/ui/PageLoader.jsx экспортирует PageSpinner и CatalogSkeleton — единая визуальная система индикации загрузки. revealStaggerStyle задаёт CSS animation delay для каскадного появления карточек.

constants/catalogFilters.js и constants/catalog.js определяют DEFAULT_CATALOG_FILTERS, PAGE_SIZE — централизация magic numbers. mediaUrl в api.js формирует абсолютные URL обложек с учётом VITE_API_URL.

Rating на AnimeDetailPage отправляет POST на API, dispatch window event anicatalog-rating для debounced обновления средних оценок в карточках каталога без полной перезагрузки страницы.

Admin-маршруты (/admin/*) lazy-loaded и защищены AdminRoute; в scope данной ВКР не детализируются, но их наличие в App.jsx не нарушает separation of concerns монорепозитория учебного проекта.

eslint.config.js с eslint-plugin-react-hooks предотвращает missing dependencies в useEffect VideoPlayer — типичный источник stale closures для currentTime handlers.

index.html содержит div#root и meta viewport; document.title может устанавливаться страницами для улучшения UX вкладок браузера.

Accessibility: icon-only кнопки плеера снабжены aria-label; дальнейшее развитие — focus trap в EpisodeModal, объявления aria-live для смены серии screen reader пользователям.

Web Vitals: loading="lazy" на постерах ниже fold улучшает LCP; фиксированный aspect-ratio карточек каталога снижает CLS при подгрузке изображений.

History API и SPA fallback: прямой заход на /watch/:id требует от web-сервера отдачи index.html — стандартная конфигурация static hosting для React Router BrowserRouter.

PWA manifest и service worker не реализованы; HTML5 video и responsive layout создают основу для future «Add to Home Screen» на мобильных устройствах.

Error boundaries на уровне маршрутов — возможное улучшение React 19; текущая обработка ошибок через try/catch в контекстах и локальные сообщения на страницах.

Сценарий «холодного старта»: AuthProvider → fetchMe → при успехе fetchFavorites и fetchCollection; иначе activateGuestSession. Индикатор loading предотвращает flash неавторизованного UI.

AnimeDetailPage: кнопки «Смотреть с начала» / «Продолжить» используют collectionMap для определения lastEpisodeId и progressSeconds, navigate на watchPath.

Горячие клавиши VideoPlayer: Space play/pause, arrows seek, F fullscreen, M mute; игнорирование при focus в input предотвращает конфликт с поиском.

Смена quality: pendingResumeRef сохраняет currentTime; qualityLoading блокирует двойные переключения до loadedmetadata нового src.

CollectionsPage: сортировка по дате просмотра, процент завершения, empty state со ссылкой на каталог.

AuthPage: валидация паролей до fetch, автоматический login после register, промо fetchAuthPageConfig.

userSettingsSync: activateAccountSession / activateGuestSession разделяют ключи localStorage между пользователями.

Ручное тестирование по чек-листу: все маршруты, фильтры URL, watch resume, skip OP, autoplay next, favorites sync — успешно при работающем API.

Независимая эволюция frontend при стабильном JSON-контракте REST — ключевой итог архитектурного решения AniHex.

TypeScript не использован; JSDoc в apiCache.js; миграция на TS — перспектива промышленного развития.

ScrollToTop сбрасывает scroll при смене pathname. HomePage минимизирует запросы, используя animeList для секций; баннеры кэшируются 60 с.

FavoritesPage переиспользует CatalogAnimeCard; пустое избранное содержит CTA на главную.

ProfileSettingsPage: nickname, email, password, site prefs, SettingsStorageBadge для объёма localStorage.

CatalogFilterPanel: жанры checkbox, тип TV/OVA/film, сезон зима/весна/лето/осень, slider года, возраст PG-13/R+, сортировка popularity/rating/year.

PlayerNextEpisodeOverlay: countdown autoplay next, cancel, Space hint; integrate nextEpisode from WatchPage props.

invalidateCache при anicatalog-reload event синхронизирует каталог после admin изменений без manual refresh пользователя.

debounce 1500 ms на anicatalog-rating предотвращает шторм запросов при массовых оценках на демо-стенде.

Vite watch ignored server/** предотвращает full-reload loop при PATCH duration episode в dev.

Тёмная тема: bg-bg-dark, accent для CTA, text-text-muted для вторичного текста — согласованность visual language.

Production npm run build → dist/ static files; preview mode с proxy для интеграционной проверки перед сдачей.

Разделение vite-project (client) и server (API) в monorepo — параллельная работа студентов дипломной группы.

Клиент не реализует хранение каталога — только fetch и cache; persistence данных полностью на стороне API сервера.

VideoPlayer persistProgress: localStorage + PATCH collection для авторизованных; guest — только local until login sync.

WatchLoading component показывает сообщение при загрузке episode data — минимальный feedback до mount VideoPlayer.

Итоговая архитектура клиента AniHex соответствует best practices SPA 2024–2026: lazy routes, context domains, fetch cache, HTML5 video custom controls.

2.3. Реализация адаптивной вёрстки для различных устройств

Breakpoints Tailwind sm/md/lg: на mobile фильтры в drawer, увеличенные touch-targets, WatchPage на 100dvh. Проверено на 360 px (смартфон), 768 px (планшет), 1280 px (ПК). Тёмная тема для длительного просмотра.

Понятие «тонкий клиент» в контексте SPA означает, что бизнес-правила валидации окончательных данных остаются на сервере, а клиент выполняет предварительную проверку и форматирование для удобства. Такой баланс предотвращает избыточное дублирование логики и сохраняет безопасность: token и права доступа проверяются backend при каждом защищённом запросе.

Жизненный цикл компонента React включает mounting, updating и unmounting; в useEffect задаётся cleanup для отмены подписок и таймеров — критично для VideoPlayer, где hideTimer и saveTimer должны очищаться при размонтировании WatchPage, иначе возможны утечки памяти и обновление state unmounted component.

Accessibility (a11y) стриминговых интерфейсов предполагает aria-label на кнопках плеера, управление с клавиатуры, достаточный контраст subtitles. В AniHex базовые aria-label добавлены на icon-only controls; дальнейшее развитие — focus trap в модальных окнах выбора серии.

Performance profiling React DevTools и Lighthouse выявляет узкие места: тяжёлые re-render CatalogPage при каждом keystroke без debounce, большие списки без мемоизации. Применённые debounce, useMemo для filtered list и lazy routes адресуют типичные проблемы.

Сравнение альтернатив React — Vue 3, Svelte, Angular — показывает, что для командного учебного проекта с разделением frontend/backend React обеспечил наибольшую документированность и знакомство команды. Svelte компилирует меньший runtime, Angular избыточен для SPA без enterprise форм.

Tailwind JIT генерирует только используемые utility-классы, уменьшая CSS bundle. Design tokens проекта (accent, bg-card, text-muted) централизованы в theme конфигурации, что упрощает смену брендинга.

History API pushState позволяет React Router менять URL без запроса к серверу; при прямом заходе на /watch/... web-server должен отдавать index.html (fallback) — стандартная настройка static hosting для SPA.

Web Vitals (LCP, FID, CLS) для медиасайта: крупные постеры влияют на LCP — используется loading="lazy" на img ниже fold; CLS минимизируется фиксированным aspect-ratio карточек в catalog grid.

CORS в production решается размещением API и static origin за одним доменом или reverse proxy; в dev Vite proxy устраняет cross-origin preflight для упрощения отладки fetch.

Progressive Web App (PWA) manifest и service worker не реализованы в scope работы, но HTML5 video и responsive layout создают foundation для будущей установки «на домашний экран» мобильного устройства.

Компонент Navbar.jsx централизует навигационные ссылки, логотип AniHex, кнопку поиска и user menu. На WatchPage navbar скрывается или минимизируется через PlayerUiContext для immersion.

Footer.jsx дублирует вторичные ссылки и copyright; исключается из watch layout. Единообразие footer/header формирует brand consistency.

EpisodeModal.jsx позволяет выбрать серию не покидая AnimeDetailPage — modal overlay с grid номеров серий, прогресс-бars просмотра, keyboard Escape закрывает.

PlaybackQueueBar.jsx fixed внизу экрана показывает текущую очередь, кнопки play/pause queue, expand list. Интеграция с QueueContext позволяет смотреть плейлист серий подряд из разных тайтлов.

SearchOverlay.jsx полноэкранный поиск с live filter по animeList, keyboard navigation результатов, Enter переходит на карточку. SearchProvider хранит open state.

utils/filterAnime.js содержит чистые функции parseGenresParam и filterAnimeList — unit-test friendly слой без React.

utils/watch.js централизует findAnimeById, findEpisode, watchPath — единый источник truth для URL просмотра.

utils/playerStorage.js и playbackQueue.js абстрагируют localStorage keys с префиксом anicatalog для избежания коллизий с другими сайтами на localhost.

utils/sitePrefs.js loadSitePrefs сохраняет autoPlayNext, preferred quality; sync с ProfileSettings.

hooks/useWatchAnime.js инкапсулирует loading/error states загрузки anime и episode для WatchPage, уменьшая размер page component.

components/ui/PageLoader.jsx экспортирует PageSpinner — SVG анимация, используемая в RouteFallback и кнопках loading.

constants/catalogFilters.js DEFAULT_CATALOG_FILTERS задаёт начальные значения year range и sort по умолчанию (popularity).

mediaUrl helper в api.js преобразует относительные пути обложек в абсолютные с учётом API_BASE.

Rating stars на AnimeDetailPage отправляют POST rating endpoint и dispatch anicatalog-rating для обновления среднего в catalog cards.

Admin routes lazy-loaded но не являются предметом пользовательского тестирования данной ВКР; их наличие не нарушает separation of concerns репозитория monorepo.

eslint.config.js обеспечивает единый code style: react-hooks rules предотвращают missing dependencies в useEffect VideoPlayer.

index.html содержит root div и meta viewport; title страницы меняется optionally через document.title в pages.

Responsive images: srcSet не используется для постеров — server отдаёт одно разрешение; для diplome достаточно, CDN optimization out of scope.

Color scheme dark по умолчанию соответствует prefs media or class on html — Tailwind dark variant.

Error boundary не глобальный — локальные try/catch; future improvement React 19 error boundaries on route level.

Сценарий «холодного старта» приложения начинается с монтирования AuthProvider и параллельного запроса fetchMe. Пока bootstrap не завершён, глобальный индикатор loading предотвращает мигание кнопки «Войти» для уже авторизованного пользователя. После получения token подгружаются избранное и коллекция; гостю активируется локальная сессия с префиксом anicatalog в localStorage, что позволяет накапливать прогресс до регистрации и перенести его на сервер при первом успешном login.

Карточка аниме на AnimeDetailPage объединяет описательные поля (синопсис, студия, жанры, возрастной рейтинг), блок рейтинга со звёздами, кнопку добавления в избранное и сетку серий с индикацией просмотренных эпизодов. Выбор «Смотреть с начала» и «Продолжить» опирается на collectionMap: если для animeId сохранён lastEpisodeId и progressSeconds, пользователь попадает на нужную серию через watchPath без ручного поиска.

Горячие клавиши VideoPlayer реализованы централизованным обработчиком keydown: пробел переключает воспроизведение, стрелки влево и вправо перематывают на фиксированный интервал, клавиши J и L — альтернативные шаги перемотки, F — полноэкранный режим, M — mute, цифры — выбор скорости из предустановленного набора. Обработчик игнорирует события, если focus находится в input или textarea, что предотвращает конфликт с формой поиска.

Смена качества видео в плеере сопровождается сохранением currentTime в pendingResumeRef перед размонтированием старого элемента video и восстановлением после loadedmetadata нового источника. Флаг qualityLoading блокирует повторные переключения до завершения загрузки метаданных, снижая риск гонок при быстрых кликах пользователя.

Интеграция очереди просмотра (QueueContext) с WatchPage позволяет после окончания серии автоматически предложить следующий элемент не только внутри одного тайтла, но и из пользовательского плейлиста, собранного на разных страницах каталога. Событие anicatalog-queue синхронизирует состояние панели PlaybackQueueBar при изменении очереди из модальных окон или карточек.

Страница CollectionsPage сортирует записи коллекции по дате последнего просмотра, отображает процент завершения и миниатюру последней просмотренной серии. Пустое состояние содержит ссылку на каталог с поясняющим текстом — паттерн empty state, снижающий растерянность нового пользователя.

Форма регистрации на AuthPage проверяет совпадение пароля и подтверждения, минимальную длину и допустимые символы логина до отправки на сервер, сокращая число ошибочных запросов. После успешной регистрации token сохраняется автоматически, и пользователь перенаправляется на главную без повторного входа.

Модуль userSettingsSync координирует запись пользовательских настроек (скорость воспроизведения, громкость, autoPlayNext) в localStorage и их отправку на сервер при наличии сессии. Функции activateAccountSession и activateGuestSession переключают пространство ключей хранилища, исключая смешение данных разных пользователей на одном браузере.

При проектировании цветовой схемы AniHex выбран тёмный фон bg-bg-dark и акцентный цвет accent для интерактивных элементов — кнопок «Смотреть», активных фильтров, прогресс-бара плеера. Такое оформление соответствует контексту просмотра видео и согласовано с визуальными привычками аудитории стриминговых сервисов.

Тестирование пользовательских сценариев проводилось вручную по чек-листу: навигация по всем маршрутам; применение комбинации фильтров с проверкой URL; воспроизведение серии с паузой и возобновлением; skip OP при наличии меток; autoplay next; добавление и удаление из избранного; регистрация нового пользователя и синхронизация коллекции. Все сценарии выполнены успешно при работающем REST API сервера проекта.

Разработка клиента AniHex подтвердила, что при чётком контракте REST API frontend может развиваться независимо: изменение вёрстки каталога или плеера не требует модификации серверного кода, если формат JSON остаётся совместимым. Это согласуется с принципами модульности и разделения ответственности, принятыми в современной веб-инженерии.

Использование TypeScript в проекте не применялось — кодовая база на JavaScript с JSDoc-комментариями в отдельных модулях; для дипломного масштаба это снижает порог входа и ускоряет итерации. При промышленном развитии платформы миграция на TypeScript повысила бы надёжность контрактов props компонентов VideoPlayer и страниц каталога.

Компонент ScrollToTop обеспечивает возврат прокрутки в начало документа при каждой смене маршрута React Router, что особенно важно при переходе из длинного каталога на короткую карточку аниме: без этого пользователь оказался бы «в середине» новой страницы.

HomePage формирует динамические секции на основе уже загруженного animeList, минимизируя число дополнительных запросов. Баннеры главной страницы запрашиваются отдельным endpoint и кэшируются на 60 секунд — компромисс между актуальностью промо и экономией трафика.

FavoritesPage переиспользует CatalogAnimeCard для визуальной согласованности с каталогом; пустой список избранного сопровождается call-to-action для перехода к подборкам главной страницы.

Проектирование интерфейса AniHex начиналось с выделения пользовательских персон: гость, зарегистрированный зритель, повторный посетитель с незавершённым просмотром. Для каждой персоны определены ключевые пользовательские сценарии: найти тайтл по жанру, продолжить серию, добавить в избранное, сформировать очередь для последовательного просмотра. Макеты страниц согласовывались с возможностями REST API.

Визуальная иерархия каталога строится на контрасте постера и типографики названия: крупный заголовок, мелкий рейтинг и жанры, метка прогресса в углу карточки. Такое решение ускоряет сканирование сетки при быстром поиске контента.

Компонент VideoPlayer проектировался итеративно: сначала базовые play/pause и progress, затем переключение качества, горячие клавиши, пропуск OP, оверлей следующей серии. Каждый этап проверялся на реальных MP4, отдаваемых через /media API.

Согласование API-контракта с backend-разработчиком включало форматы JSON для anime, episode и collection item. Документация основных endpoints приведена в таблице 1 настоящей работы.

Риски на стороне клиента: рост объёма animeList в памяти компенсируется порционным отображением; XSS через nickname предотвращается экранированием React; потеря token решается повторным входом на /auth.

Экономическая эффективность SPA: один раз загруженный bundle обслуживает все маршруты; статические assets могут раздаваться через CDN при росте аудитории.

Кэш каталога на 45 секунд уменьшает повторные запросы при навигации и снижает нагрузку на сервер при активном просмотре каталога.

Педагогическая ценность работы: демонстрация полного цикла frontend — от теории SPA до production-сборки, интеграции с API и UX-полировки (скелетоны, debounce, sticky-фильтры).

Сопоставление с коммерческими аниме-платформами: AniHex воспроизводит ключевые UX-паттерны discovery и watch, достаточные для учебной демонстрации специализированного стримингового клиента.

Объём реализованного клиентского кода — десятки компонентов и тысячи строк JavaScript/JSX, что соответствует масштабу индивидуальной выпускной квалификационной работы по разработке программного обеспечения.

Заключение

В ходе выполнения выпускной квалификационной работы [ФИО студента] разработана клиентская часть веб-платформы AniHex для просмотра японских мультипликационных сериалов. Теоретический анализ подтвердил целесообразность архитектуры SPA на React для интерактивных стриминговых сервисов, а также значимость UX-паттернов каталога, персональных разделов и полноэкранного видеоплеера.

Практически реализованы маршрутизация с ленивой загрузкой страниц, контексты Auth/Anime/Queue/PlayerUi/Search, каталог с фильтрами и URL-state, компонент VideoPlayer на HTML5 video, страницы авторизации, избранного, коллекции и профиля, клиентский кэш API и skeleton-loading. Интеграция с сервером выполнена исключительно через Fetch API к REST endpoints; детали серверного хранения данных в работе не рассматривались.

Поставленная цель достигнута: создана веб-платформа (frontend), обеспечивающая зрителю доступ к каталогу аниме и воспроизведению серий в браузере. Все задачи, сформулированные во введении, выполнены. Разработанное приложение имеет практическую значимость как пользовательский интерфейс учебного проекта AniHex и демонстрирует применение современного стека React + Vite + Tailwind при построении специализированного стримингового клиента.

Перспективы связаны с расширением тестового покрытия, улучшением доступности (a11y) плеера и возможной оптимизацией первого contentful paint. Полученные компетенции в проектировании SPA и работе с видео в браузере применимы в профессиональной веб-разработке медиасервисов.

Автор выражает благодарность научному руководителю за методическую поддержку и одногруппнику, разработавшему серверное REST API, за согласование форматов данных и своевременное предоставление тестового стенда. Совместная работа над AniHex наглядно продемонстрировала эффективность разделения frontend и backend в рамках одного учебного продукта.

Материалы настоящей работы (текст в формате HTML, презентация presentation.html, речь speech.md) образуют единый комплект для защиты выпускной квалификационной работы по направлению разработки веб-платформы для просмотра японских мультипликационных сериалов в ГАПОУ «Московский университет», Москва, 2026 год. Исходный код клиентской части размещён в репозитории учебного проекта vite-project и может быть воспроизведён комиссией по инструкции npm install и npm run dev при наличии запущенного серверного API.
