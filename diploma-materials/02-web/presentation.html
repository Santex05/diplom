Раздел 1

Актуальность и проблема

Зрителю нужен удобный интерфейс: поиск тайтла, просмотр серии, личные списки. Без продуманного клиента даже хороший API не превращается в сервис.

Многостраничный сайт (MPA)

  • Полная перезагрузка страницы
  • Медленные переходы
  • Сложно сохранять состояние UI

SPA на React (AniHex)

  • Мгновенная навигация
  • Единый стиль и контексты
  • Кэш данных на клиенте

Серверная логика, БД и Docker — отдельные темы соавторов. Здесь только браузерный клиент для зрителя.

Раздел 2

Цель, задачи и объект исследования

Цель: разработать клиентскую часть веб-платформы AniHex для просмотра аниме.

  • Спроектировать маршруты и структуру страниц
  • Реализовать каталог с фильтрами и поиском
  • Разработать HTML5-видеоплеер и страницу просмотра
  • Внедрить авторизацию, избранное, коллекцию, прогресс
  • Оптимизировать UX загрузки (скелетоны, кэш API)

Объект: веб-клиент стриминговой платформы. Предмет: SPA на React с интеграцией REST API.

Раздел 5

Каталог и фильтрация

Фильтрация выполняется на клиенте функциями filterAnimeList и parseGenresParam — данные приходят одним запросом GET /api/anime.

  • Жанры (логика AND), тип, сезон, год, возрастной рейтинг
  • Поиск с debounce, состояние фильтров в URL
  • Подгрузка карточек при скролле (infinite scroll)
  • CatalogSkeleton при первой загрузке

Раздел 9

Тестирование клиентской части

  • Автотесты: npm run test:client — нормализация жанров (tests/genres.test.js)
  • Линтер: npm run lint — ESLint для src/
  • Production: npm run build → статика в dist/
  • Ручной чек-лист: все маршруты, фильтры URL, watch resume, skip OP, favorites sync

Интеграция проверялась при работающем REST API (локально npm run dev:server + npm run dev).
