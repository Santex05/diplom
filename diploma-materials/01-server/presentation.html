Раздел 1

Актуальность и проблема

Онлайн-просмотр аниме требует централизованного каталога, учёта пользователей и безопасной выдачи видео. JSON-файлы подходят только для прототипа.

JSON (прототип)

  • Быстрый старт без СУБД
  • Нет транзакций
  • Сложно работать команде

PostgreSQL + API (AniHex)

  • Целостность данных
  • REST для клиента и админки
  • Готовность к продакшену

Раздел 2

Цель, задачи, методы

Цель: разработать серверную логику платформы AniHex.

  • Спроектировать схему БД и REST API
  • Реализовать пользователей: регистрация, избранное, коллекция
  • Разработать админ-API с отдельной авторизацией
  • Загрузка и перекодирование серий (ffmpeg)

Стек backend: Node.js, Express 5, PostgreSQL, Multer, ffmpeg.

Клиентское приложение и развёртывание — отдельные темы соавторов; здесь только сервер и API.

Раздел 7

Административное API

Я выбрал REST API + отдельные токены adm_, потому что:

  • Админка — SPA, ей нужен JSON API, а не HTML-формы
  • Админ и пользователь не должны делить сессии
  • CRUD через HTTP: POST/PUT/DELETE для аниме, серий, баннеров
