## Слайд 2 — Актуальность и проблема

Без контейнеров перенос проекта на другой компьютер или VPS часто ломается: разные версии Node и PostgreSQL, разные пути к видео, ручная настройка nginx. Для защиты диплома и передачи заказчику нужен один сценарий «склонировал — запустил — работает». Docker Compose решает это: декларативное описание сервисов, изоляция зависимостей, сохранение данных в томах на хосте. Актуальность — сокращение времени развёртывания с часов ручной настройки до минут.

Объект — развёртывание веб-платформы. Предмет — Docker, Compose, nginx, VPS.

## Слайд 4 — Состав контейнерного стека

Три контейнера. db — официальный postgres:16-alpine, хранит каталог и пользователей. api — собирается из server/Dockerfile: Node.js 22, в образ добавлен ffmpeg для перекодирования видео при загрузке (логика в коде соавтора, но утилита должна быть в контейнере). web — корневой Dockerfile: статика React после npm run build и nginx для отдачи файлов. Снаружи пользователь видит только порт 80 — API и Postgres не торчат в интернет напрямую. Данные на диске хоста — папка docker-data.

---

## Слайд 5 — Docker Compose: зависимости и сеть

В docker-compose.yml сервис api зависит от db с condition service_healthy — healthcheck через pg_isready. API не стартует, пока база не готова, иначе будут ошибки подключения. DATABASE_URL указывает на хост db внутри docker-сети, не localhost. Команда запуска для проверяющего: docker compose up -d --build. Флаг --build пересобирает образы после изменений в Git. На слайде — порядок: db healthy → api up → web up → сайт на localhost.

---

## Слайд 6 — Dockerfile образов api и web

Образ API: Alpine, установка ffmpeg, npm ci по package.json сервера, копирование server/, точка входа node index.js. Тома монтируют anime, banners, avatars в /data — видео не запекаются в образ, иначе при rebuild терялись бы гигабайты. Образ web — двухстадийная сборка: первая стадия npm run build, вторая — nginx:alpine копирует dist/ и deploy/nginx.conf. Так production-образ web весит мегабайты, а не гигабайты с node_modules.

---

## Слайд 7 — Конфигурация nginx

nginx в контейнере web выполняет две роли. Для пути / отдаёт статику SPA с try_files — React Router работает при прямом заходе на /catalog или /watch. Для /api и /media — proxy_pass на http://api:3001. client_max_body_size 512m — иначе nginx отрежет загрузку больших серий в админке. Заголовки X-Real-IP и X-Forwarded-For передают IP клиента в API для логирования. На VPS перед compose часто ставят второй nginx или Caddy на хосте для HTTPS — Certbot + Let's Encrypt.

---

## Слайд 8 — Тома docker-data и переносимость

На хосте каталог docker-data: postgres/ — файлы СУБД; anime/ — видео и постеры; banners/, avatars/ — медиа CMS. При docker compose down контейнеры удаляются, но тома на диске остаются. Перенос на другой ПК: скопировать проект и docker-data, установить Docker, compose up — получаем тот же сайт с контентом. На слайде — скриншот docker compose ps (все Up) и localhost с главной страницей.

---

## Слайд 9 — Переменные окружения и инициализация БД

Ключевые переменные в compose: DATABASE_URL для api; ADMIN_PASSWORD — секрет админки; ANIME_DIR=/data/anime; VIDEO_TRANSCODE для включения ffmpeg. Файл schema.sql монтируется в /docker-entrypoint-initdb.d/ Postgres — таблицы создаются при первом запуске db. Если есть старый JSON-каталог, импорт: docker compose exec api npm run db:migrate. Секреты на VPS хранят в .env с правами chmod 600, не коммитят в Git.

## Слайд 10 — Развёртывание на VPS и проверка

По DEPLOY.md: аренда VPS Ubuntu, установка Docker, git clone, при переносе — rsync docker-data, .env с паролями, docker compose up -d --build, проверка curl localhost, A-запись DNS, HTTPS через Certbot, cron для бэкапа docker-data и pg_dump. Проверка на защите: показать compose ps, открыть localhost, при необходимости — логи docker compose logs api при загрузке серии (виден ffmpeg). CI/CD в полном виде не реализован — описан как перспектива; для ВКР достаточен воспроизводимый локальный и VPS-цикл.

## Возможные вопросы жюри

**Почему три контейнера, а не один?**  
Разделение: БД, API и статика обновляются и масштабируются независимо; nginx не смешивается с Node.

**Где хранятся видео?**  
В томе docker-data/anime на хосте — не внутри образа api.

**Как перенести на другой ПК?**  
Скопировать репозиторий + docker-data, Docker, compose up -d --build.

**Зачем ffmpeg в образе api?**  
При загрузке серий нужно перекодирование; без ffmpeg в контейнере админка не сможет обработать видео в Docker-среде.

**Почему API не смотрит наружу?**  
Только web на :80 — единая точка входа, проще TLS и безопасность.

**Почему не рассказываете про REST API?**  
Endpoints реализовал соавтор; я обеспечиваю сеть и proxy /api → api:3001.

**Почему не рассказываете про React?**  
Frontend собирается в dist/ на стадии build; nginx только отдаёт файлы.
