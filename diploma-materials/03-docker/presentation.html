Раздел 1

Актуальность и проблема

Команда разрабатывала backend и frontend отдельно. Без единого окружения на защите возникает риск «у меня работает» — разные версии Node, Postgres, пути к видео.

СпособПлюсыМинусы
Локально npm run devБыстрая разработкаНе воспроизводит production
Ручная установка на VPSГибкостьДолго, ошибки конфигурации
Docker ComposeОдин запуск, одинаковое окружениеТребуется Docker на хосте

Реализация REST API и React-клиента — темы соавторов. Здесь только инфраструктура: контейнеры, тома, nginx, DEPLOY.md.

Раздел 2

Цель, задачи и объект исследования

Цель: контейнеризировать и автоматизировать деплой платформы AniHex.

  • Описать сервисы db, api, web в docker-compose.yml
  • Собрать образ API (Node + ffmpeg) и web (Vite → nginx)
  • Настроить reverse proxy и лимиты загрузки видео
  • Обеспечить сохранность данных в docker-data при перезапуске
  • Задокументировать развёртывание в DEPLOY.md

Объект: процесс развёртывания веб-платформы. Предмет: Docker, Compose, nginx, VPS.

Раздел 4

Docker Compose: зависимости и сеть

  • depends_on api → db с condition: service_healthy
  • healthcheck db: pg_isready — API не стартует до готовности Postgres
  • Внутренняя сеть compose: api обращается к db:5432
  • Наружу проброшен только WEB_PORT (по умолчанию 80)
  • Запуск: docker compose up -d --build

Раздел 6

Конфигурация nginx

  • / — try_files для SPA (React Router)
  • /api и /media — proxy_pass на http://api:3001
  • client_max_body_size 512m — загрузка видео через админку
  • Заголовки X-Real-IP, X-Forwarded-For для логов API
